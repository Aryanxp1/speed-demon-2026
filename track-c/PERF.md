Key ideas, in order of what they were worth:

- Records are found with no data-dependent branch: AVX2 masks of quotes, commas and LFs, a carry-less multiply for the inside-quotes mask, five structural positions per record, quote counts by rank queries, digits decoded four records at a time.
- Every name lookup is a cache miss, so a batch prefetches the region entry and the name bucket in one pass and reads them in the next; the locked bit-matrix line is prefetched for write one pass before its `fetch_or`.
- Names are 64-bit hashes in one-line buckets of 8 slots (47-bit tag and a dense number in one u64, claimed by one CAS); the dense numbers keep the distinct-name bit matrix at 4 MiB on huge pages.
- Name numbers are reserved per worker in blocks of 32: the one shared counter per first appearance was the hottest contended line (box 31.7 ms to 23.9).
- Fixed costs: workers start as a tree and each zeroes one huge page while the regions load; claims are released with `MADV_DONTNEED` so exit does not tear down the mapping on one thread.

## November 2: compact hot tables with retained overflow capacity

The incoming verified best is run-012b0c9fd050 at 45884261: T=0.022297 s, M=10,858,496 bytes, S=289, D=1, K=44.410192, **82.374132 points**, all gates passed. An unchanged-build later run measured 82.064825, illustrating native timing/memory variation. Historical 82.4+ estimates above are not claimed official measurements.

Reviewed the user-supplied C:/Users/aryan/Downloads/5pm/bc/track-c source/log, externally reported 82.877 points and K=45.451492. Adapted its 16K name buckets, compact hot bit rows, fixed-eight delimiter extraction and removal of a redundant ASCII XOR into our existing Rust parser and join. The supplied hard 241-group / 104,320-name matrix limit is not adopted: our layout reserves the existing 256 groups and 131,072 IDs, placing overflow words and extra groups outside the compact hot area. A checked block reservation prevents ID wrap. Hot buckets and rows fit in the first two huge pages; cold overflow is touched only when required. No hash-function change, dependency or build-setting change.

The mmap loader now checks mapping success and appends a missing final LF in private writable padding, including page-aligned EOF. This does not modify input files. The existing parser, tree worker launch, region join, statistics, CLI and immediate exit remain. Names retain the existing probabilistic fingerprint matching; reducing the bucket index from fifteen to fourteen bits reduces the effective fingerprint by one bit, and universal exactness is not claimed.

Actual offline Cargo release builds deny warnings. All 11 independent reference datasets pass at 1/4/12 CPU affinities and AddressSanitizer at 1/12 affinities. These include full/sample/tiny and other seeds, hostile quoted CSV/Unicode/BOM/negative amounts, 110,000 distinct names exercising cold overflow, 255 country groups plus unmatched, missing LF, and page-aligned EOF. Full-data bytes match the official Python reference on every timing and memory run. Source has 319 nonblank Rust plus seven Dockerfile lines, predicting S=326.

Nineteen alternating pairs per variant with full-output checking show approximately tied local wall times. Compact tables alone were not faster; adding delimiter and digit changes reduced that cost. The final variant's baseline / adaptation wall medians were 17.713 / 17.581 ms; median per-pair wall gain was -0.677%. Pairwise timings are noisy and are not official speed evidence.
